# WorldFarm 美术零门槛与玩法优先开发路线

## 1. 文档目的

本文用于固化 WorldFarm 的早期开发路线，核心目标是避免项目卡在美术、3D 建模、界面精修上，先用低成本、可替换、可商用的方式把玩法系统跑通。

本路线不否定最终美术质量，而是把美术投入分阶段：

```text
先证明玩法值得做
-> 再做可视化占位
-> 再替换统一风格素材
-> 最后投入专属美术
```

当前原则：

- 不因为缺少正式美术而暂停玩法开发。
- 不把单个 3D 作物模型打磨作为早期主线任务。
- 所有外部素材必须先确认授权，再进入项目。
- 所有临时素材都要能被后续正式素材替换。
- 先用手机真机验证可读性和操作手感，再决定是否继续精修。

## 2. 推荐总路线

WorldFarm 采用 6 阶段推进：

```text
阶段 1：文字 / 控件玩法原型
阶段 2：色块地图 / 几何占位版
阶段 3：CC0 素材可视化版
阶段 4：统一风格改造版
阶段 5：AI 3D + Blender 专属补充版
阶段 6：正式美术生产版
```

优先级顺序：

| 优先级 | 路线 | 当前判断 |
| --- | --- | --- |
| 1 | 占位先行 | 现在就执行，是主路线 |
| 2 | 免费商用素材库 | 适合原型和早期可视化 |
| 3 | Unity/Tuanjie 光照和材质统一 | 尽早做基础规范 |
| 4 | AI 3D 工具辅助 | 适合重点资产，不适合完全依赖 |
| 5 | 低成本外包 | 玩法和风格稳定后再做 |
| 6 | Substance 3D Designer 等重型纹理工具 | 后期再考虑，不作为当前主线 |

## 3. 阶段 1：文字 / 控件玩法原型

### 3.1 目标

用最简单的 UI 验证核心玩法，不追求最终界面表现。

适合验证：

- 本地时间成熟。
- 播种、成熟、收获。
- 地貌适应系数。
- 低适应地貌的低产和变异机会。
- 国家解锁。
- 国家声望。
- 订单循环。
- 研究点。
- 加工系统。
- 名产认证。
- 一级变异。
- 二次育种。

### 3.2 允许的占位方式

| 对象 | 占位方式 |
| --- | --- |
| 作物 | 文本、颜色块、简单球体 / 圆柱 / 胶囊体 |
| 地块 | 纯色矩形、简单网格、按钮卡片 |
| 国家 | 列表、标签页、色块地图 |
| 地貌 | 文本标签 + 颜色区分 |
| 订单 | 表格、按钮、库存数字 |
| 变异 | 线索物品、标签、简单颜色标记 |
| 加工 | 进度条、队列文本 |
| 育种 | 亲本选择框、结果列表 |

### 3.3 验收标准

阶段 1 只验收玩法，不验收美术。

必须满足：

- 玩家能完成至少 10 分钟的连续测试。
- 每个按钮在手机上容易点击。
- 每个系统的输入、产出、消耗、奖励能看清楚。
- 所有核心状态能存档并重新读取。
- 随机系统必须有调试按钮，避免测试被概率拖慢。

不验收：

- UI 是否最终好看。
- 作物模型是否真实。
- 地貌是否有最终地图表现。
- 动画、音效、转场。

## 4. 阶段 2：色块地图 / 几何占位版

### 4.1 目标

在玩法原型通过后，用色块和简单几何体建立空间感。

重点验证：

- 国家地貌在界面上的摆放方式。
- 一个地貌区域里放几个地块槽位最舒服。
- 不规则地貌区域是否比标准方格更有特色。
- 手机竖屏下是否能看清多个地块和作物状态。
- 点击、拖动、缩放、切换国家是否顺手。

### 4.2 推荐表现

```text
国家地图 = 一个可滚动 / 可缩放的区域
地貌 = 不规则色块区域
地块槽 = 地貌区域内的标准种植点
作物 = 简单几何体或低模素材
```

不建议一开始做完全规则的棋盘式农场。WorldFarm 的卖点之一是国家和地貌差异，因此应该尽早验证“不规则地貌区域 + 标准槽位”的方案。

### 4.3 地貌区域规则

- 地貌区域可以是不规则大小。
- 每个地貌区域内部放 1-4 个标准地块槽。
- 早期国家基础地貌 2-3 个槽位，高级地貌 1-2 个槽位。
- 稀有变异地貌可以只有 1 个槽位，提高稀缺感。
- 地貌区域大小不直接等于地块数量，避免视觉和数值强绑定。

## 5. 阶段 3：CC0 素材可视化版

### 5.1 目标

使用免费商用素材库替换一部分占位内容，让游戏进入“可看、可玩、可继续测试”的状态。

当前推荐素材来源：

| 素材来源 | 推荐用途 | 判断 |
| --- | --- | --- |
| Quaternius | 作物、生长阶段、收获物、部分自然道具 | 已导入作物包，适合作物原型 |
| Kenney | UI 图标、地块、小镇建筑、装饰、瓦片、简单模型 | 适合补齐农场和经营界面素材 |

### 5.2 授权规则

外部素材进入项目必须记录：

- 素材名称。
- 下载地址。
- 作者 / 组织。
- 授权协议。
- 是否允许商用。
- 是否要求署名。
- 是否允许修改。
- 导入日期。
- 本项目用途。

当前已知方向：

- Kenney 官方资产通常以 CC0 发布，可商用，署名不是强制要求；实际使用时仍以具体资产页为准。
- Quaternius Ultimate Crops Pack 官方页面标注 CC0，适合当前作物原型；实际使用时仍保留来源记录。
- Unity Asset Store 资源不能默认当作 CC0，必须按具体资源的 Asset Store License 或作者说明处理。

### 5.3 使用原则

CC0 素材不是最终风格的保证，只是低风险底座。

使用时要做三类标记：

| 标记 | 含义 |
| --- | --- |
| `prototype_only` | 只用于验证，不作为正式版 |
| `style_base` | 可作为风格底座，后续统一改造 |
| `final_candidate` | 质量和风格接近正式资产，可长期保留 |

不要因为某个免费素材“看起来还行”就默认锁定为最终资产。所有长期保留素材都要经过风格统一和手机预览。

## 6. 阶段 4：统一风格改造版

### 6.1 目标

把不同来源的素材统一成 WorldFarm 自己的视觉底座。

统一内容：

- 模型比例。
- 轴心和朝向。
- 地块摆放高度。
- 材质亮度。
- 色彩饱和度。
- 阴影强度。
- 轮廓圆润程度。
- UI 图标线宽和颜色。
- 作物成熟阶段大小。
- 远距离识别效果。

### 6.2 Unity/Tuanjie 中优先做的事情

优先使用轻量方案：

- 正交相机。
- 偏俯视经营视角。
- 高环境光。
- 柔和主光。
- 弱阴影。
- 简化 PBR 或 Toon-like 材质。
- 少量统一色板。
- 移动端真机截图校验。

不急着使用：

- 复杂后处理。
- 重型 Shader。
- 高精度纹理。
- 大量实时灯光。
- 复杂反射。

### 6.3 风格目标

WorldFarm 第一阶段视觉目标：

```text
明亮、圆润、低压力、可读性强、国家地貌差异明确的世界农场。
```

参考商业游戏时只提炼方向，不复制具体设计。

允许提炼：

- 明亮氛围。
- 圆润比例。
- 柔和阴影。
- 低压力经营感。
- 清晰的资源反馈。
- 易读的作物和建筑轮廓。

禁止复制：

- 具体建筑造型。
- 具体 UI 构图。
- 具体图标。
- 具体地图结构。
- 角色形象。
- 可识别的商业素材。

## 7. 阶段 5：AI 3D + Blender 专属补充版

### 7.1 目标

AI 3D 工具只作为“专属资产补充”，不作为全部美术主流程。

适合 AI 3D 的资产：

- 重点作物普通版。
- 重点变异作物。
- 国家代表建筑初稿。
- 地貌装饰物。
- 活动素材。
- 外包前的参考模型。

不适合 AI 3D 的任务：

- 大批量完全统一资产。
- 需要严格拓扑和 UV 的最终移动端模型。
- 需要复杂动画绑定的角色或机械结构。
- 需要像参考图完全一致的模型。

### 7.2 标准流程

```text
资产需求表
-> 文本提示词 / 自有参考
-> AI 生成 3-6 个方向
-> 选择最接近方向
-> Blender 修轮廓、面数、轴心、缩放、材质
-> Unity/Tuanjie 导入
-> 预览场景验收
-> Android 真机检查
-> 通过后标记为 final_candidate
```

### 7.3 授权要求

使用 Meshy、Tripo AI 等工具前，必须确认当前账号套餐是否允许商业使用。

原则：

- 免费档如果不允许商用，不能产出正式资产。
- 如果免费档要求署名，必须记录署名要求。
- 付费档也不能上传侵权参考图。
- 不上传其它商业游戏截图去直接生成可替代模型。
- AI 生成资产仍要保留生成日期、工具、账号套餐、提示词和后处理记录。

## 8. 阶段 6：正式美术生产版

### 8.1 启动条件

满足以下条件后再开始大规模正式美术生产：

- 核心种植循环稳定。
- 一级变异验证通过。
- 加工系统验证通过。
- 初级育种验证通过。
- 地貌地图交互方式确定。
- 首发国家范围确定。
- 作物数量和生长阶段范围确定。
- 风格规范通过手机预览。

### 8.2 外包适用范围

适合外包：

- 首发国家代表地貌。
- 关键作物普通版。
- 关键变异作物。
- 加工建筑。
- 国家建筑皮肤。
- UI 图标套装。
- 商店图、宣传图、Logo 优化。

不建议外包：

- 还没有验证的玩法系统素材。
- 可能频繁改规则的界面。
- 数量很大但规格还没定的作物全集。

### 8.3 外包交付要求

每个外包需求必须写清楚：

- 资产名称。
- 用途。
- 视角。
- 尺寸比例。
- 面数预算。
- 材质数量。
- 贴图尺寸。
- 文件格式。
- Unity/Tuanjie 导入要求。
- 是否需要源文件。
- 是否允许商业使用。
- 是否允许修改。
- 是否包含著作权转让或独占授权。
- 是否保证未使用侵权素材。

## 9. 工具选择建议

### 9.1 当前推荐

| 工具 / 资源 | 当前用途 | 是否主线 |
| --- | --- | --- |
| Unity/Tuanjie IMGUI | 玩法原型 | 是 |
| Unity/Tuanjie 简单 3D | 色块地图和几何占位 | 是 |
| Quaternius | 作物和生长阶段占位 | 是 |
| Kenney | UI、建筑、地块、小镇素材占位 | 是 |
| Blender | 修模型、统一比例、导出 FBX | 是 |
| PureRef | 内部参考板 | 可选 |
| Meshy / Tripo AI | 重点资产初稿 | 可选 |
| Substance 3D Designer | 后期程序化纹理 | 暂缓 |

### 9.2 Substance 暂缓原因

Substance 3D Designer 很强，但当前不作为主线：

- 学习成本高。
- 订阅成本高。
- 当前项目更缺玩法验证，不缺精细纹理。
- 早期用简单材质、色板、顶点色和轻量贴图即可支撑测试。

后期如果地貌和建筑量稳定，再考虑用它批量做：

- 土壤材质。
- 水田材质。
- 沙壤 / 盐碱地材质。
- 火山灰材质。
- 温室玻璃材质。
- 加工建筑表面材质。

## 11. 决策规则

开发时按下面规则做取舍：

| 情况 | 决策 |
| --- | --- |
| 玩法没验证，美术需求很复杂 | 先占位 |
| 一个模型反复修改超过 2 轮仍不稳定 | 暂停精修，回到结构化资产流程 |
| 素材授权不清楚 | 不进入项目 |
| 免费素材风格不完全统一 | 先标记为 prototype_only |
| 手机上看不清 | 优先调比例、色彩和镜头，不先加细节 |
| 玩法系统影响资产规格 | 先定玩法，再定资产 |
| AI 生成结果接近但不干净 | Blender 清理后再进 Unity |
| 同类资产要批量制作 | 先做 1 个基准资产并验收 |

## 12. Git 和项目管理规则

### 12.1 提交规则

提交到 Git 的内容：

- 设计文档。
- Unity 场景源文件。
- 脚本。
- Prefab。
- 材质。
- 源模型。
- 贴图。
- 外部素材授权说明。

不提交：

- Unity `Library`。
- 本地日志。
- APK 构建产物。
- 临时下载包。
- 工具缓存。

### 12.2 外部素材目录建议

外部素材建议统一放置：

```text
UnityProject/Assets/WorldFarm/External/
UnityProject/Assets/WorldFarm/ExternalLicenses/
```

每个素材库保留一份说明：

```text
ExternalLicenses/Kenney/README.md
ExternalLicenses/Quaternius/README.md
```

说明内容：

- 素材库名称。
- 官方地址。
- 授权协议。
- 下载日期。
- 使用范围。
- 是否改动。

当前 Quaternius 作物包已经在项目中作为原型素材使用，后续应补齐对应授权记录文档。

## 13. 关键结论

- WorldFarm 当前继续坚持玩法优先，不再被作物模型细节卡住。
- 文字 / 控件原型是当前主线，直到加工、认证和育种都能跑通。
- CC0 素材库是早期可视化主力，不是最终美术承诺。
- AI 3D 是重点资产补充工具，不是批量生产主流程。
- 外包应在风格规范和玩法范围稳定后启动。
- Substance 等重型工具后置，避免当前阶段过早增加复杂度。
- 所有素材最终都要通过手机真机可读性、授权、风格统一和性能预算四类验收。
