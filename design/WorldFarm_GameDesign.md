# WorldFarm 游戏设计

## 1. 游戏定位

WorldFarm 是一款轻量经营向种菜游戏。玩家从中国农场开始，通过种植、收获、订单、图鉴和探索任务获得资源，再逐步解锁世界各国版图地块。每个国家拥有自己的地块、作物品种、订单主题和料理加工线，形成“种植收集 + 世界地图扩张 + 国家特色作物图鉴”的长期目标。

核心原则：

- 地块归属国家，作物必须种在允许的国家地块上。
- 成熟时间按本地设备时间计算，离线也能自然成长。
- 国家解锁走全球地图路线，不要求先解锁完中国全部作物。
- 重叠作物用“物种 + 国家品种”处理，避免图鉴混乱。
- 地貌作为区域容器展示，区域内放多个标准地块槽；作物按适应系数决定产量和变异概率。

细化文档：

- [地貌、适应系数与变异系统设计](WorldFarm_BiomeMutationDesign.md)
- [国家与地貌设计](WorldFarm_CountryBiomeDesign.md)

## 2. 核心循环

1. 玩家选择一个已解锁国家版图。
2. 在该国家地块上种植本国允许的作物品种。
3. App 根据本地时间计算作物成长阶段和成熟状态。
4. 玩家收获产物，获得金币、经验、国家声望、图鉴进度和订单材料。
5. 玩家完成订单或图鉴目标，得到探索点、国家通行证碎片、建筑材料。
6. 玩家在世界地图中选择下一个国家或扩展当前国家地块。
7. 新国家带来新地块、新作物、新订单和新加工品。

## 3. 本地时间成熟机制

### 3.1 数据记录

每次播种时记录：

| 字段 | 说明 |
| --- | --- |
| `plotId` | 地块 ID |
| `cropVariantId` | 作物国家品种 ID |
| `plantedAtEpochMillis` | 播种时的本地系统时间戳 |
| `matureAtEpochMillis` | 预计成熟时间戳 |
| `lastCheckedEpochMillis` | 上次进入游戏或刷新时的本地系统时间戳 |
| `growthSeconds` | 标准成长秒数 |
| `boostSeconds` | 肥料、天气、建筑等加速秒数 |
| `state` | `empty / growing / mature / withered` |

成熟计算：

```text
effectiveGrowthSeconds = max(1, growthSeconds - boostSeconds)
matureAtEpochMillis = plantedAtEpochMillis + effectiveGrowthSeconds * 1000
remainingMillis = matureAtEpochMillis - nowEpochMillis
```

### 3.2 离线成长

不需要后台常驻。玩家再次打开游戏或回到前台时，对所有种植中地块执行一次刷新：

```text
如果 nowEpochMillis >= matureAtEpochMillis，则 state = mature
否则继续显示剩余时间
```

通知可以后置开发，不影响核心逻辑。以后要做成熟提醒时，再用 `AlarmManager` 或 `WorkManager` 根据最近成熟作物安排通知。

### 3.3 改本地时间的处理

本游戏可以接受单机本地时间，但需要软性防作弊，避免明显破坏数值：

- 如果 `nowEpochMillis < lastCheckedEpochMillis`，判定设备时间回拨，暂停成长刷新，只更新 `lastCheckedEpochMillis` 提示状态。
- 如果单次离线跨度超过上限，例如 72 小时，只结算最多 72 小时成长，超出部分不直接产出。
- 使用 `SystemClock.elapsedRealtime()` 记录本次运行内时间，App 前台期间优先用单调时间推进倒计时，减少系统时间跳动导致的 UI 闪烁。
- 单机版本不做强封禁，只做收益上限和异常提示；以后接服务器再用服务器时间校验。

## 4. 世界版图与国家地块

### 4.1 基础概念

| 概念 | 说明 |
| --- | --- |
| 国家 `Country` | 世界地图上的一个可解锁区域，例如中国、日本、泰国、墨西哥 |
| 地块 `LandPlot` | 归属于某个国家的可种植格子 |
| 地貌 `Biome` | 地块环境标签，例如水田、旱田、高原、温室、热带 |
| 作物物种 `CropSpecies` | 抽象物种，例如水稻、玉米、辣椒 |
| 作物品种 `CropVariant` | 绑定国家和地貌的可种植版本，例如中国水稻、日本粳米、泰国茉莉香米 |
| 产物 `ProduceItem` | 收获后进入仓库的物品，可带国家来源标签 |

### 4.2 种植限制

一块地能否种作物，由三组条件决定：

```text
plot.countryId 必须在 cropVariant.allowedCountryIds 中
plot.biome 必须匹配 cropVariant.requiredBiomes
player 必须已解锁 cropVariant.unlockRequirement
```

例子：

| 作物品种 | 可种国家 | 需要地貌 | 说明 |
| --- | --- | --- | --- |
| 中国水稻 | 中国 | 水田 | 初始中期作物 |
| 日本粳米 | 日本 | 水田 | 日本解锁后获得 |
| 泰国茉莉香米 | 泰国 | 水田 / 热带水田 | 泰国特色高价值水稻 |
| 墨西哥玉米 | 墨西哥 | 旱田 | 墨西哥代表作物 |
| 法国葡萄 | 法国 | 温带田 / 果园 | 加工线接葡萄汁、葡萄酒 |

### 4.3 初始中国

中国作为新手国家，负责教会基本系统，但不承担所有前置解锁。

初始内容建议：

| 阶段 | 内容 | 目标 |
| --- | --- | --- |
| 新手 1 | 华北麦田、小麦 | 学会播种和收获 |
| 新手 2 | 江南水田、水稻 | 学会地貌限制 |
| 新手 3 | 订单站、白菜订单 | 学会资源循环 |
| 新手 4 | 世界地图入口 | 开始选择下一国家 |

中国后续仍保留高级内容，例如茶叶、莲藕、荔枝、人参、竹笋、花椒，但这些不阻挡玩家出海。

## 5. 跨国重叠作物处理

现实中很多国家作物重叠，例如水稻、小麦、玉米、土豆、葡萄、辣椒。设计上不要把“同名作物”简单重复，也不要因为一个国家先有水稻就禁止其他国家做水稻。

推荐方案：物种唯一，品种多国。

### 5.1 图鉴层

图鉴分两层：

| 层级 | 示例 | 用途 |
| --- | --- | --- |
| 物种图鉴 | 水稻 | 让玩家理解这是同一大类作物 |
| 品种图鉴 | 中国水稻、日本粳米、泰国茉莉香米 | 展示国家特色、数值差异和收集目标 |

玩家第一次种出任意水稻时，解锁“水稻”物种条目。之后每解锁一个国家水稻品种，就点亮该物种下的国家徽章。

### 5.2 种植层

种植时选择的是 `CropVariant`，不是抽象 `CropSpecies`。

例如：

| 物种 | 国家品种 | 只能种在哪里 | 差异 |
| --- | --- | --- | --- |
| 水稻 | 中国水稻 | 中国水田 | 成长稳定、基础订单多 |
| 水稻 | 日本粳米 | 日本水田 | 料理价值高 |
| 水稻 | 泰国茉莉香米 | 泰国热带水田 | 成长较慢、售价高 |
| 玉米 | 中国玉米 | 中国旱田 | 初级饲料线 |
| 玉米 | 墨西哥玉米 | 墨西哥旱田 | 墨西哥订单和料理核心 |

这样既保留国家限制，又不会让玩家觉得同名作物冲突。

### 5.3 仓库层

仓库可以采用两种策略：

策略 A：基础产物共享，来源标签单独记录。

```text
produceSpeciesId = rice
originCountryId = cn / jp / th
quality = normal / fine / premium
```

优点是仓库不会爆炸，适合轻量游戏。订单需要国家特色时，再要求 `rice + originCountryId=jp`。

策略 B：产物完全拆分。

```text
cn_rice_grain
jp_koshihikari_grain
th_jasmine_rice_grain
```

优点是辨识度强，适合深度收集和加工。缺点是背包和订单复杂度更高。

当前建议用策略 A。等玩法变深后，只把少数高价值特色品种拆为独立产物。

### 5.4 平衡规则

重叠作物的差异不只换名字，至少有一个有效差异：

- 成熟时间不同
- 售价或订单权重不同
- 需要地貌不同
- 加工产物不同
- 国家声望收益不同
- 可参与的料理、节日或任务不同

如果一个作物在多个国家没有明显差异，就作为共享品种处理：

```text
variantId = common_wheat
allowedCountryIds = ["cn", "fr", "us", "au"]
produceSpeciesId = wheat
```

共享品种仍然受国家地块限制，收获时根据地块生成来源标签。

## 6. 解锁顺序设计

### 6.1 不采用“中国全清后出海”

不要把中国设计成一个必须清空的大章节。中国只负责新手引导和一条长期成长线。玩家完成少量中国目标后，就应该打开世界地图。

建议开启世界地图的条件：

```text
玩家等级 >= 4
完成 8 次收获
完成 3 个订单
解锁 2 种中国作物
```

这通常在第一天内完成，不要求解锁茶叶、莲藕、人参等中国高级作物。

### 6.2 全球解锁资源

引入通用资源“探索点”：

| 资源 | 来源 | 用途 |
| --- | --- | --- |
| 探索点 `explorePoint` | 每日订单、图鉴、国家声望升级、成就 | 解锁国家 |
| 国家声望 `countryReputation` | 在该国家种植、完成该国订单 | 解锁本国高级地块和作物 |
| 地块许可 `landPermit` | 世界地图任务、活动、金币购买 | 扩建地块 |

国家解锁消耗探索点，国家内部深度消耗本国声望。这样玩家可以先扩大全球版图，也可以回头深挖某个国家。

### 6.3 世界地图分层

世界地图采用“区域池 + 自由选择”结构：

| 层级 | 解锁条件 | 可选国家示例 |
| --- | --- | --- |
| 起点 | 默认 | 中国 |
| 全球入门池 | 完成中国新手目标 | 日本、泰国、墨西哥、法国 |
| 区域扩展池 | 拥有任意 2 个国家 | 印度、埃及、意大利、美国、巴西 |
| 生态挑战池 | 拥有任意 5 个国家且等级达标 | 秘鲁、荷兰、越南、摩洛哥、澳大利亚 |
| 高级专题池 | 特定成就或活动 | 冰岛温室、沙漠绿洲、安第斯高原 |

关键点：池子解锁看全球进度，不看“中国完成度”。池子内国家由玩家选择，避免线性卡关。

### 6.4 国家内部解锁

每个国家内部可以有自己的小路线：

```text
国家解锁 -> 2 块基础地 -> 2-3 个基础作物
国家声望 2 -> 第 3 块地 + 特色作物
国家声望 4 -> 加工建筑或特殊地貌
国家声望 6 -> 高级订单与稀有品种
```

国家内部做深度，全球地图做广度，两条成长线互不完全阻塞。

## 8. 数值框架

### 8.1 作物成长时长

前期必须短，让玩家能理解循环；中后期拉长，用订单和加工承接等待。

| 类型 | 成熟时间 | 用途 |
| --- | --- | --- |
| 新手作物 | 30 秒 - 3 分钟 | 教学、即时反馈 |
| 基础作物 | 5 - 30 分钟 | 日常订单 |
| 中级作物 | 1 - 4 小时 | 离线回收 |
| 高级作物 | 6 - 12 小时 | 长线目标 |
| 稀有作物 | 24 小时以上 | 活动、图鉴、特殊订单 |

### 8.2 收益公式

基础公式：

```text
harvestAmount = baseYield + plotBonus + toolBonus
sellValue = basePrice * countryMarketFactor * qualityFactor
xpGain = ceil(growthMinutes * xpRate)
countryReputationGain = cropVariant.reputationValue
```

### 8.3 国家差异

每个国家至少有一个明确玩法偏向：

| 国家类型 | 偏向 |
| --- | --- |
| 中国 | 作物种类丰富，教学和基础订单稳定 |
| 日本 | 高品质、小产量、高料理价值 |
| 泰国 | 热带作物售价高，成长时间略长 |
| 墨西哥 | 玉米和辣椒订单链，部分作物成长快 |
| 法国 | 果园和葡萄加工价值高 |
| 巴西 | 经济作物高收益，但仓储压力更大 |

## 10. Android 端模块拆分建议

第一版可以保持简单，但接口要为后续扩展留位置：

| 模块 | 职责 |
| --- | --- |
| `data/config` | 读取国家、地块、作物 JSON |
| `data/save` | SQLite 或 SharedPreferences 存档 |
| `domain/time` | 本地时间、成熟判断、防回拨 |
| `domain/farm` | 播种、收获、地块校验 |
| `domain/world` | 国家解锁、地图池、探索点 |
| `ui/farm` | 农场主界面 |
| `ui/worldmap` | 世界地图和国家选择 |
| `ui/storage` | 仓库和订单 |

当前工程先保留单 Activity 首页雏形。进入实际开发时，优先落地 `CropSpecies / CropVariant / LandPlot / PlantedCrop` 四个核心模型，再做种植和收获。

## 12. 关键设计结论

- 成熟时间用本地时间戳计算，前台用单调时间优化倒计时，离线回到游戏时统一结算。
- 地块绑定国家和地貌，作物绑定国家品种和地貌要求，种植校验以 `CropVariant` 为准。
- 重叠作物采用“物种唯一，品种多国”的结构，图鉴清楚，玩法也能做出国家差异。
- 世界地图用探索点和解锁池推进，完成少量中国新手目标即可出海，不需要中国全作物毕业。
- 国家内部声望用于深挖本国高级作物，全球探索点用于扩大全球版图，两条进度分离。
