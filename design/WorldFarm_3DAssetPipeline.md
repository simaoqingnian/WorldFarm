# WorldFarm 3D 资产开发流程与风格规范

## 1. 文档目的

本文用于固化 WorldFarm 后续 3D 作物、地貌、地块、建筑和界面展示模型的开发方法，目标是让素材生产过程可控、可复用、可验收，并长期保持风格统一。

本项目不把“一句话直接生成最终 3D 模型”作为主流程，而采用：

```text
程序化 demo / 灰模验证
-> 2D 概念图确认方向
-> 3D 模型制作或 AI 初模清理
-> Unity/Tuanjie Prefab 化
-> 统一预览场景验收
-> Android 实机检查
-> 满意后锁定为正式资产规范
```

这样可以把主观审美拆成可检查的步骤，避免每次素材都靠随机生成结果碰运气。

## 2. 当前结论

当前优先级是：先固定 WorldFarm 的 3D 美术风格规范，再批量制作正式素材。

原因：

- 作物、地貌、地块、变异品种都会长期扩展，早期风格如果不固定，后期资产会显得杂乱。
- 作物需要在手机竖屏和农场地块中远距离识别，轮廓和比例比细节更重要。
- 变异机制会产生大量派生模型，必须先固定“普通作物”和“通用变异”的视觉语言。
- 目前的大胡萝卜 demo 用于验证 3D 展示、灯光、触控旋转和 Android 构建链路，不作为最终美术质量标准。

## 3. 已确认基础风格 v0.1

确认日期：2026-08-28

WorldFarm 第一版采用：

```text
风格名称：轻写实圆润农场 3D
核心感受：干净、温和、明亮、可识别，有一点夸张但不幼稚
目标平台：安卓手机，竖屏优先
主要视角：农场经营界面使用偏俯视 3D，详情页允许单个作物旋转展示
建模方向：中低面数、圆润大轮廓、少碎细节
材质方向：干净色块 + 少量柔和高光 + 少量生长纹理
色彩方向：自然作物色为主，不做过暗、过灰、过脏的写实风
```

### 3.1 已确认参数

| 项目 | 已确认选择 |
| --- | --- |
| 目标参考 | 接近无尽冬日的流畅和建模质感，但更明亮、更农场、更温暖 |
| 可爱程度 | B：轻写实圆润，可爱但不幼稚 |
| 是否拟人化 | 不拟人化。作物可以可爱，但不长脸、不长手脚 |
| 主视角 | A：竖屏偏俯视 3D，适合农场经营 |
| 颜色调性 | B：温暖自然 |
| 单屏作物数量 | 20 个左右 |
| 变异夸张程度 | B：中等变化，有明显地貌特征 |
| 第一批基准资产 | 胡萝卜、白菜、水稻、茶树、中国温带平原地块 |

### 3.2 作物比例

作物在地块中的识别优先级高于真实比例。

建议规则：

- 普通蔬菜类可以比真实比例更大、更饱满。
- 根茎类突出主体轮廓，例如胡萝卜、萝卜、红薯要让根部成为第一视觉。
- 叶菜类突出叶片层次和中心结构，例如白菜、菠菜、生菜。
- 谷物类突出穗、株丛和成熟色，例如水稻、小麦、玉米。
- 果树类允许更明显的树冠和果实挂点，避免果实太小导致远看不可见。
- 作物放在地块里时，成熟阶段的高度建议占地块视觉高度的 55%-85%。
- 详情展示时可以放大到屏幕中心，使用更高精度模型或更清晰材质。
- 因为主界面同屏目标是 20 个左右，普通作物可以保留更完整的轮廓细节，但仍要避免过多叶片和小装饰。

### 3.3 轮廓规则

每个作物都要满足“三秒识别”：

- 远看能一眼认出作物类别。
- 黑色剪影仍能区分根茎、叶菜、谷物、果树。
- 不依赖小字、复杂纹理或很细的局部装饰来识别。
- 变异品种要在轮廓或大色块上区别普通品种，不能只靠微小颜色变化。

### 3.4 材质规则

第一版建议使用简化 PBR 或 Unity Standard/Lit 材质：

| 类型 | 建议 |
| --- | --- |
| 作物主体 | 低金属度，粗糙度中等，少量柔和高光 |
| 叶片 | 颜色明亮但不过曝，可有轻微厚度感 |
| 土壤 | 暖色、低反光，不抢作物主体 |
| 水田 | 可以有反光，但要控制亮度，避免遮挡作物 |
| 变异装饰 | 可使用局部高光、晶体、霜边、裂纹、蜡质层 |

禁用倾向：

- 不做照片级脏污写实贴图。
- 不使用过多高频噪声。
- 不把材质做得过暗，手机屏幕上会损失识别度。
- 不让作物整体金属化，除非是特殊活动或幻想变异。

### 3.5 模型复杂度

第一版按安卓竖屏、主界面同屏 20 个左右作物进行预算：

| 资产类型 | 建议三角面数 | 材质数量 | 说明 |
| --- | ---: | ---: | --- |
| 地块中普通作物 | 600-2500 | 1-2 | 主界面同屏 20 个左右时使用，可保留清晰轮廓 |
| 详情页作物 | 2000-6500 | 1-3 | 单个展示，可更精细 |
| 果树/茶树类 | 1200-4000 | 2-3 | 树冠和果实需要更多轮廓 |
| 小型地貌道具 | 100-800 | 1 | 石头、木牌、小渠、草丛 |
| 地貌区域模型 | 1000-6000 | 2-5 | 不规则区域、梯田、水面、边缘装饰 |

后续如果单屏会显示大量作物，需要提供 LOD 或简化版本。

## 4. 标准开发流程

### 4.1 阶段 A：玩法/镜头 demo

目的：先验证游戏里是否好看、好用、流畅。

做法：

- 用 Unity 程序化模型、简单几何、占位材质快速搭建。
- 重点检查镜头距离、地块比例、点击区域、动画节奏、手机性能。
- 不追求最终美术细节。

当前大胡萝卜 demo 属于此阶段。

### 4.2 阶段 B：风格基准包

在正式批量制作前，先做 5 个基准资产：

| 基准资产 | 覆盖问题 |
| --- | --- |
| 胡萝卜 | 根茎类作物比例、圆润主体、叶簇设计 |
| 白菜 | 叶菜类层次、叶片边缘、中心结构 |
| 水稻 | 谷物类株丛、穗、成熟色 |
| 苹果树或茶树 | 多年生作物、树冠、果实挂点 |
| 中国温带平原地块 | 地块尺寸、土壤、边缘、作物落点 |

只有当这 5 个基准资产的风格被确认，才进入批量国家作物制作。

### 4.3 阶段 C：单个正式资产制作

每个正式资产按以下顺序：

1. 填写资产需求卡。
2. 生成或绘制 2D 概念图，给 2-3 个方向。
3. 选中一个方向后制作灰模或程序化模型。
4. 进入 Blender 或其他建模工具制作正式模型。
5. 导出 FBX/GLB，并保留源文件。
6. 导入 Unity/Tuanjie。
7. 设置材质、缩放、朝向、阴影、Prefab。
8. 放入 AssetPreview 场景检查。
9. 构建 Android APK 实机查看。
10. 通过验收后锁定版本。

### 4.4 阶段 D：批量扩展

批量制作必须建立在基准资产已通过的前提下。

批量规则：

- 同一国家同一地貌的作物共用色彩和材质倾向。
- 同一作物类别共用比例规则，例如所有根茎类都有近似的主体夸张程度。
- 同一变异类型共用视觉符号，例如耐寒都有霜边/蓝绿倾向。
- 所有资产必须经过统一预览场景，不直接进入主场景。

## 6. 用户反馈格式

为了让修改可控，反馈尽量落在具体维度上：

```text
整体方向：喜欢 / 不喜欢 / 接近但要调整
比例：太胖 / 太瘦 / 太高 / 太小 / 顶部太重
颜色：太暗 / 太亮 / 太灰 / 太真实 / 太卡通
材质：太塑料 / 太粗糙 / 太平 / 高光太强
轮廓：远看不清 / 叶子太乱 / 主体不够明显
风格一致性：和当前基准一致 / 不一致
手机效果：屏幕中太小 / 太暗 / 旋转不好看 / 帧率不稳
结论：继续深化 / 换方向 / 锁定
```

无效反馈示例：

```text
再好看一点
更高级一点
感觉不对
```

这些反馈可以作为主观感受，但需要再拆成比例、颜色、材质、轮廓、动画或屏幕效果。

## 7. 变异资产视觉规则

变异不只改数值，也要从外观上让玩家理解“它适应了某种环境”。

### 7.1 通用变异模板

| 变异类型 | 触发地貌倾向 | 视觉语言 | 数值方向 |
| --- | --- | --- | --- |
| 耐旱型 | 旱田、沙地、戈壁 | 颜色更深，叶片更窄，表面干裂纹，根茎更粗短 | 低水分适应提高，高湿地貌减产 |
| 耐寒型 | 高原、寒地、冻土 | 蓝绿偏色，霜白边缘，植株紧实矮壮 | 低温适应提高，热带地貌减产 |
| 耐湿型 | 水田、湿地、雨林 | 叶片更大更亮，茎部水润，局部反光 | 高水分适应提高，干旱地貌减产 |
| 耐盐碱型 | 盐碱地、海岸滩涂 | 灰绿/银白点缀，表面盐晶，叶缘硬挺 | 盐碱适应提高，肥沃平原略减产 |
| 高山型 | 高原、山地、梯田 | 矮壮、颜色浓、叶片厚，根系感更强 | 高海拔适应提高，低海拔普通地貌减产 |
| 热带型 | 热带雨林、亚热带果园 | 颜色更鲜艳，叶片宽大，果实或主体更饱满 | 高温高湿适应提高，寒地减产 |
| 沙漠型 | 沙漠、绿洲边缘 | 蜡质表面、硬边、少量刺状装饰、颜色偏金橙 | 极端干热适应提高，水田减产 |

### 7.2 稳定变异品种规则

当普通作物在低适应地貌中变异并稳定为新品种后：

- 新品种拥有自己的独立资产和 Prefab。
- 新品种回到原本高适应地貌时会减产。
- 稳定品种不再沿原路线重复变异。
- 图鉴中记录来源：原作物、触发地貌、变异方向。
- 视觉上必须继承原作物的核心轮廓，同时加入对应变异模板的特征。

示例：

```text
普通水稻 -> 旱田低适应试种 -> 耐旱稻
普通白菜 -> 高原寒地试种 -> 雪芯白菜
普通胡萝卜 -> 西北沙地试种 -> 赤岩胡萝卜
普通玉米 -> 高原冷田试种 -> 紫穗高原玉米
```

## 9. 预览与验收

后续建议新增 `AssetPreview.unity` 场景，专门用于检查资产。

预览场景应固定：

- 相机角度。
- 灯光强度。
- 背景颜色。
- 标准地块大小。
- 作物默认缩放。
- 详情页展示缩放。
- Android 竖屏画幅。

验收清单：

```text
地块中远看是否能识别
详情页旋转时正面、侧面、背面是否都成立
颜色是否与现有基准资产一致
材质是否过亮、过暗、过塑料
模型是否穿插地面
叶片或果实是否遮挡主体
成长阶段是否能看出差异
变异特征是否明确
手机上是否流畅
APK 构建是否成功
```

## 10. 自动化方向

后续可以为 WorldFarm 增加 Unity 编辑器自动化：

| 工具 | 作用 |
| --- | --- |
| `WorldFarmAssetImportPostprocessor` | 导入模型时自动统一缩放、材质、压缩和命名检查 |
| `WorldFarmPrefabBuilder` | 根据模型和材质自动生成作物 Prefab |
| `WorldFarmPreviewCapture` | 自动生成预览图和图鉴图 |
| `WorldFarmAssetValidator` | 检查缺失材质、面数过高、命名不规范、Prefab 缺数据 |
| `WorldFarmBuildAndroidDebugApk` | 构建安卓测试包 |

当前已有 `WorldFarmProjectBootstrap`，负责项目初始化、场景配置和 Android Debug APK 构建。

## 11. 已确认后的执行流程

第一版基础风格已经确认，下一步进入“风格基准包”阶段。

执行顺序：

1. 建立 `AssetPreview.unity` 资产预览场景。
2. 固定预览相机、灯光、地块尺寸、背景和 Android 竖屏画幅。
3. 制作第一批基准资产的程序化/灰模版本。
4. 先验收胡萝卜、白菜、水稻、茶树、中国温带平原地块的统一风格。
5. 通过后再进入正式模型、材质、Prefab、图标和成长阶段。
6. 每次基准资产更新后构建 Android APK，优先用手机实机看亮度、大小、轮廓和流畅度。

第一批验收重点：

| 资产 | 验收重点 |
| --- | --- |
| 胡萝卜 | 根茎类比例、顶部叶簇、成熟体积、详情页旋转效果 |
| 白菜 | 叶菜类层次、叶片边缘、中心结构、远距离识别 |
| 水稻 | 谷物类株丛、穗、成熟色、地块中密集显示效果 |
| 茶树 | 多年生作物、树冠形态、采摘感、山地/丘陵气质 |
| 中国温带平原地块 | 土壤颜色、田埂边缘、作物落点、主界面画面基调 |

## 12. 后续仍可补充的信息

以下信息不影响立刻开工，但会影响长期质量，可以在对应功能开始前再确认：

- 你希望游戏更偏休闲收菜，还是偏策略经营？
- 是否希望有昼夜、天气、季节变化？
- 是否希望地貌有明显国家文化元素，例如中国田埂、日本梯田、法国薰衣草田？
- 作物是否需要成长阶段都有明显外观变化？
- 是否希望有收获动画、成熟闪光、变异发现演出？
- 是否能接受使用 Blender 作为正式建模工具？
- 是否能接受 AI 生成概念图，再由 Blender/Unity 清理成正式资产？
- 是否需要模型和图标都保持同一套视觉规范？

## 14. 资产预览反馈记录

### 14.1 第一轮预览反馈

反馈日期：2026-08-28

结论：

- 整体方向：可以。
- 颜色：可以。
- 最满意资产：茶树。
- 最不满意资产：胡萝卜。
- 手机显示问题：水稻显示超出了右侧屏幕边界。
