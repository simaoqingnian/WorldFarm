# WorldFarm 经济、加工、名产与育种系统设计

## 1. 设计结论

经济、加工和育种需要互相支撑，而不是各自独立。

推荐采用：

- 一个统一订单系统，按频道区分日常、国家、名产、加工、研究和活动订单。
- 作物经济价值不只来自订单高价，还来自加工、名产认证、育种亲本、图鉴、国家声望和研究材料。
- 加工建筑不要为每个作物单独建一个工厂，而是设计少量加工线建筑，每个建筑通过配方、模块和国家皮肤扩展内容。
- 名产认证不是永久品种属性，而是每次收获批次的产地和品质标记。
- 国家声望是“国家内深挖进度”，主要解锁该国高级地貌、作物、订单、认证、加工模块和研究合作；新国家解锁仍主要由世界探索点承担。
- 研究点用于解锁育种、加工和变异控制能力，可以提高指定组合的成功率，但要避免变成全局无脑加成。
- 二次育种底层使用可调环境参数，但前期用“环境配方 + 少量强化项”包装，后期再开放精细调参。
- 育种结果不只有成功和失败，还要有目标组合、旁支变异、亲本回退、不稳定种子、稀有突破等分支。

## 2. 作物经济用途

作物至少承担 6 类经济用途。

| 用途 | 作用 | 示例 |
| --- | --- | --- |
| 基础出售 | 处理库存溢出，提供保底金币 | 普通水稻直接出售 |
| 订单交付 | 主经济循环，推动金币、经验、国家声望 | 中国饭馆要水稻，日本便当店要粳米 |
| 加工生产 | 提升低价作物价值，形成产业链 | 水稻 -> 米饭 / 米酒，小麦 -> 面粉 / 面包 |
| 名产认证 | 体现国家和地貌特色 | 波尔多葡萄园产出的葡萄获得波尔多认证 |
| 育种材料 | 让变异品种不只卖钱 | 耐旱稻可作为干旱育种亲本 |
| 图鉴与声望 | 支撑收集、国家扩张和长期目标 | 首次发现霜心稻提升高原研究声望 |

不要把名产和变异全部压到“价格更高”一个出口。更好的结构是：

```text
基础作物 -> 日常订单 / 初级加工 / 直接出售
国家品种 -> 国家订单 / 国家声望 / 国家加工配方
名产认证批次 -> 名产合约 / 高级加工 / 风土样本
稳定变异品种 -> 特殊订单 / 育种亲本 / 图鉴收集
组合变异品种 -> 高级合约 / 稀有加工 / 高阶育种素材
```

## 3. 统一订单系统

订单底层保持统一，玩家界面按频道展示。

```text
订单中心
  日常
  中国
  日本
  法国
  名产
  加工
  研究
  活动
```

### 3.1 订单频道

| 订单频道 | 目的 | 需求类型 | 主要奖励 |
| --- | --- | --- | --- |
| 全球日常委托 | 消耗基础作物，保证日常循环 | 普通作物、低级加工品 | 金币、经验 |
| 国家订单 | 推动国家声望和国家解锁 | 本国作物、本国加工品 | 金币、国家声望、国家材料 |
| 名产合约 | 消耗产地认证、风土变异和代表作物 | 指定产地、指定品质、指定认证 | 高金币、风土样本、稀有配方 |
| 加工订单 | 消耗加工品，提升产业链价值 | 米饭、面粉、酒、腌菜、茶饮等 | 高金币、建筑经验、配方熟练度 |
| 研究订单 | 消耗变异线索、样本、特殊作物 | 不稳定种子、风土样本、变异作物 | 研究点、育种配方、环境配方 |
| 活动订单 | 承载节日和限时玩法 | 活动作物、主题加工品 | 活动货币、限定装饰、限定种子 |

国家不需要各自独立一套订单系统。系统统一，但订单条件可以带国家、地貌和认证要求。

### 3.2 订单需求字段

订单需求不要只写 `itemId` 和数量。为了支持国家、名产和变异，需要允许多种过滤条件。

```json
{
  "orderId": "fr_bordeaux_wine_contract_01",
  "channel": "specialty_contract",
  "countryId": "fr",
  "requiredItems": [
    {
      "itemType": "crop_harvest",
      "speciesId": "grape",
      "originBiomeId": "fr_bordeaux_vineyard",
      "requiredCertifications": ["bordeaux_origin"],
      "requiredTraits": ["thick_skin", "wine_aroma"],
      "minQuality": "B",
      "count": 8
    }
  ],
  "rewards": {
    "coins": 1800,
    "countryReputation": {
      "fr": 35
    },
    "researchPoints": 12,
    "researchItems": ["sample_bordeaux_gravel_soil"]
  }
}
```

这允许订单表达：

- 要某个物种，例如葡萄。
- 要某个国家品种，例如法国葡萄。
- 要某个地貌产地，例如波尔多葡萄园。
- 要某个名产认证，例如波尔多认证。
- 要某个变异性状，例如厚皮、酒香。
- 要某个加工品，例如葡萄酒、米酒、腌番茄。

### 3.3 经济资源

不建议做多个国家金币。金币保持全局，国家特色通过声望和样本体现。

| 资源 | 是否全局 | 用途 |
| --- | --- | --- |
| 金币 | 全局 | 买种子、升级地块、基础建筑、普通加工 |
| 世界探索点 | 全局 | 解锁新国家、新地图路线 |
| 国家声望 | 按国家区分 | 解锁该国高级地貌、作物、订单和加工配方 |
| 研究点 | 全局或按研究方向 | 解锁育种、变异稳定、加工技术、环境配方 |
| 风土样本 | 按地貌区分 | 名产合约、高级育种、认证升级 |
| 配方熟练度 | 按加工配方区分 | 提高加工稳定性、减少时间、解锁高阶版本 |

例如法国订单不发“法国金币”，而是发：

```text
金币
法国声望
波尔多砾石土样本
酒庄合约券
酿造熟练度
```

### 3.4 国家声望和世界探索点的分工

| 进度 | 范围 | 主要作用 | 设计目的 |
| --- | --- | --- | --- |
| 世界探索点 | 全局 | 解锁新国家、新大陆路线、全球地图节点 | 保证玩家可以较早接触世界内容 |
| 国家声望 | 单国家 | 解锁该国内部高级内容 | 让玩家回到已解锁国家继续深挖 |

关键规则：

- 不能要求玩家把中国声望刷满才能解锁下一个国家。
- 解锁新国家主要看世界探索点和少量新手目标。
- 国家声望用于解锁该国内部的高级地貌、作物、名产、订单和加工内容。
- 高级跨国内容可以同时要求两个国家的声望，但只用于后期目标，不阻塞基础出海。

## 4. 国家声望系统

国家声望是每个国家独立的长期进度。它不只是解锁地貌，也承担国家特色内容的开放节奏。

### 4.1 国家声望来源

| 来源 | 说明 |
| --- | --- |
| 国家订单 | 完成该国订单获得该国声望 |
| 名产合约 | 提交该国认证名产，获得较高声望 |
| 首次种植 / 首次收获 | 首次完成该国代表作物，获得一次性声望 |
| 首次认证 | 首次获得某个地貌名产认证，获得一次性声望 |
| 图鉴收集 | 解锁该国作物、变异、加工品图鉴条目 |
| 研究提交 | 提交该国风土样本或变异样本 |
| 加工熟练度 | 使用该国配方达到熟练度里程碑 |
| 活动任务 | 节日或限时国家主题任务 |

重复订单可以提供稳定声望，但需要日上限或衰减，避免玩家只刷一个短订单把国家内容全部推完。

### 4.2 国家声望用途

| 用途 | 说明 | 示例 |
| --- | --- | --- |
| 解锁地貌 | 最基础用途，开放该国更多地貌区域和地块槽 | 法国声望 2 解锁卢瓦尔河谷菜园 |
| 解锁作物品种 | 开放该国本土作物和高级国家品种 | 日本声望 3 解锁抹茶茶树 |
| 解锁订单层级 | 提高国家订单品质和奖励 | 法国声望 4 出现酒庄订单 |
| 解锁名产认证 | 开放该国认证资格、认证等级或认证机构 | 法国声望 5 开放波尔多认证 |
| 解锁加工配方 | 开放国家料理、饮品、酒类、腌制品 | 中国声望 3 解锁米酒，法国声望 4 解锁葡萄酒 |
| 解锁加工模块 / 皮肤 | 让少量加工建筑表现出国家特色 | 发酵工坊安装橡木桶模块 |
| 解锁研究合作 | 开放该国风土样本、育种项目和研究加成 | 日本声望 5 解锁雪融水田育种配方 |
| 解锁贸易路线 | 允许该国名产进入跨国订单 | 法国葡萄酒出口到全球名产订单 |
| 提高商店库存 | 解锁种子、样本、装饰、建筑模块购买权限 | 墨西哥声望提高辣椒种子库存 |
| 展馆 / 成就 | 国家收集度奖励 | 中国声望等级奖励国家农场装饰 |

国家声望的奖励要以“内容开放”为主，不建议给过强全局产量加成。可以给少量便利性加成，例如订单刷新次数、认证手续费降低、种子商店库存增加。

### 4.3 国家声望等级示例

每个国家可以有 10 个声望等级，第一版可以只实现 5 个。

| 等级 | 定位 | 可解锁内容示例 |
| --- | --- | --- |
| 0 | 初到国家 | 2 块基础地，2-3 个基础作物，基础国家订单 |
| 1 | 熟悉本地 | 第 3 块基础地，基础加工配方，种子商店扩容 |
| 2 | 地貌扩展 | 解锁第二个地貌或地貌槽位扩建 |
| 3 | 特色作物 | 解锁代表作物、高级国家订单 |
| 4 | 加工深化 | 解锁国家加工模块、国家料理或饮品 |
| 5 | 名产认证 | 解锁代表地貌名产认证和名产合约 |
| 6 | 风土研究 | 解锁该国风土样本、环境配方、研究订单 |
| 7 | 高级地貌 | 解锁稀有地貌，例如高原、火山、冰原、绿洲 |
| 8 | 跨国贸易 | 开放该国名产出口和跨国组合订单 |
| 9 | 专家合作 | 开放高阶育种项目和认证升级 |
| 10 | 国家大师 | 国家展馆奖励、长期称号、稀有装饰 |

### 4.4 中国早期声望示例

中国作为初始国家，声望不能卡住出海，只负责让玩家逐步理解系统。

| 中国声望 | 解锁内容 |
| --- | --- |
| 0 | 华北旱田 2 槽、江南水田 2 槽、城郊菜畦 2 槽，小麦、水稻、白菜 |
| 1 | 玉米、萝卜、农家厨房基础配方 |
| 2 | 华北旱田 +1 槽、城郊菜畦 +1 槽，国家订单刷新 |
| 3 | 丘陵梯田 1 槽、茶叶、谷物磨坊 |
| 4 | 米酒、面粉、茶饮基础加工 |
| 5 | 江南水田名产认证、初级风土样本 |
| 6 | 西北沙壤，耐旱相关研究订单 |
| 7 | 高原冷田，霜心 / 雪芽方向研究 |

出海条件建议独立：

```text
完成新手订单 8 个
解锁中国声望 2
获得世界探索点 100
```

这个条件让玩家第一天就可以打开全球路线，但中国仍有很多内容可回头深挖。

## 5. 作物加工系统

加工系统的目标是让作物价值产生差异，而不是简单地把作物变成更贵的物品。

加工应该解决这些问题：

- 基础作物太多时，有稳定消耗出口。
- 同一种作物的不同品种有不同用途。
- 名产认证和变异性状能进入经济循环。
- 国家特色不只体现在地貌名字上，也体现在料理、饮品和商品上。
- 长周期作物有更高附加值，短周期作物有批量消耗价值。

### 5.1 是否需要很多加工厂

不建议一开始设计很多加工厂，也不建议每个作物一个加工厂。

推荐结构：

```text
少量加工建筑大类
  + 建筑等级
  + 可安装模块
  + 国家配方
  + 名产配方
  + 熟练度
```

建筑数量要少，配方数量可以多。

这里的“同一建筑”指底层建筑类型相同，不是视觉必须完全一样。实际设计可以让多个国家拥有自己的加工厂皮肤、模块和配方，但它们都挂在同一个建筑类型下。

```text
建筑类型 BuildingType：发酵工坊
  通用表现：普通发酵桶、陶罐、木架
  中国江南皮肤：米酒坊、陶缸、蒸饭台
  日本皮肤：清酒酿造间、木桶、曲房
  法国波尔多皮肤：酒庄、橡木桶、葡萄压榨台
  意大利托斯卡纳皮肤：石墙酒窖、橄榄和葡萄模块
```

玩家感受到的是“不同国家有不同加工建筑风格和配方”，但系统实现上仍然是：

```text
少量建筑类型
  + 国家皮肤 Skin
  + 功能模块 Module
  + 配方包 RecipePack
  + 建筑等级和熟练度
```

也就是说，“法国酒庄”和“日本清酒间”可以在画面上长得很不一样，但它们都属于 `fermentation_workshop`，共用排队、耗时、加速、产出、熟练度、订单提交等基础逻辑。

| 层级 | 是否按国家变化 | 说明 |
| --- | --- | --- |
| 建筑类型 | 少量固定，不随国家无限增加 | 农家厨房、谷物磨坊、发酵工坊、烘干坊、腌制坊、精炼坊 |
| 建筑皮肤 | 可以按国家变化 | 改外观、动画、小装饰，不单独创造新系统 |
| 功能模块 | 可以按国家或地貌解锁 | 橡木桶模块、清酒模块、米酒模块、茶叶烘干模块 |
| 配方包 | 可以按国家变化 | 中国米酒、日本清酒、法国葡萄酒、意大利葡萄酒 |
| 熟练度 | 按配方或加工线记录 | 玩家长期制作某类产品会更稳定、更高质 |

第一版推荐采用“全局加工区”：

- 玩家在主农场拥有少量加工建筑。
- 解锁国家后，通过国家声望获得该国配方包、模块或皮肤。
- 例如先有通用发酵工坊；法国声望达到 4 后解锁葡萄酒配方；法国声望达到 5 后解锁酒庄皮肤和橡木桶模块。
- 这样不需要每个国家地图都单独建一套加工设施，开发和操作都更轻。

中后期可以升级为“国家本地加工点”：

- 中国地图里看到江南米酒坊。
- 日本地图里看到清酒酿造间。
- 法国地图里看到波尔多酒庄。
- 但它们仍然是同一个 `fermentation_workshop` 类型的不同实例，使用同一套生产逻辑。

两种方式可以兼容：

| 阶段 | 推荐表现 | 原因 |
| --- | --- | --- |
| 前期 | 全局加工区 + 国家配方包 | 系统简单，玩家不用频繁切国家找加工厂 |
| 中期 | 全局加工区 + 可切换国家皮肤 | 增强国家特色，不增加太多操作负担 |
| 后期 | 国家本地加工点 + 全球订单中心 | 地图沉浸感更强，适合长期内容 |

不是每个国家都必须拥有每个建筑的独立皮肤。只有当国家特色足够强、玩家经常使用、能支撑订单或名产玩法时，才制作国家皮肤和专属模块。其它情况可以共用通用皮肤，只解锁国家配方。

第一版建议只做 3 个建筑：

| 建筑 | 覆盖加工线 | 示例 |
| --- | --- | --- |
| 农家厨房 | 简单料理、基础打包 | 米饭、蔬菜拼盘、煮玉米、蘑菇汤 |
| 谷物磨坊 | 谷物、粉类、基础烘焙前置 | 面粉、米粉、玉米粉 |
| 发酵工坊 | 酒、酱、茶饮、发酵食品 | 米酒、葡萄酒、泡菜、发酵茶 |

中期扩展到 6 个左右：

| 建筑 | 主要用途 | 解锁时机 |
| --- | --- | --- |
| 农家厨房 | 普通料理、国家菜品 | 初期 |
| 谷物磨坊 | 粮食加工 | 初期 |
| 发酵工坊 | 酒、酱、泡菜、发酵茶 | 中期 |
| 烘干坊 | 茶叶、香料、果干、药草 | 中期 |
| 腌制坊 | 盐渍、酸菜、海风名产 | 中期偏后 |
| 精炼坊 | 油、糖、香精、稀有提取物 | 后期 |

后续国家特色不要靠新建 50 个工厂，而是靠模块和皮肤：

| 国家 / 地貌 | 建筑表现 | 实际系统 |
| --- | --- | --- |
| 法国波尔多 | 酒庄皮肤、橡木桶模块 | 仍属于发酵工坊 |
| 中国江南 | 米坊皮肤、蒸饭模块 | 仍属于农家厨房 / 谷物磨坊 |
| 日本 | 和食厨房皮肤、清酒模块 | 仍属于厨房 / 发酵工坊 |
| 意大利托斯卡纳 | 橄榄和葡萄模块 | 仍属于发酵工坊 / 精炼坊 |

这样美术上有国家特色，代码和数值上仍然是可管理的少数系统。

        "outputQualityBonus": 0.12
      }

### 5.3 加工如何体现作物差异

作物差异可以进入加工的四个位置：

| 位置 | 说明 | 示例 |
| --- | --- | --- |
| 是否可加工 | 某些作物只能进入特定加工线 | 小麦可磨粉，葡萄可酿酒 |
| 产出数量 | 高产型性状提高数量 | 巨实玉米多出玉米粉 |
| 产出品质 | 品质风味性状提高品质 | 清香稻提高米酒品质 |
| 解锁特殊产物 | 特定名产或组合性状触发特殊配方 | 霜旱清香稻可做雪泉米酒 |

不要所有变异都只加售价。更好的例子：

| 变异性状 | 加工表现 |
| --- | --- |
| 甜 | 酒、甜品、果干品质提高 |
| 厚皮 | 腌制、窖藏、运输订单更有优势 |
| 清香 | 茶饮、米酒、汤品品质提高 |
| 霜心 | 冷食、甜品、高级料理订单更有价值 |
| 耐盐 | 腌制、海岸国家订单、保存期加工更有价值 |
| 早熟 | 加工倍率普通，但批量订单效率高 |
| 巨大化 | 单个基础售价高，加工数量收益高，但品质未必高 |

## 6. 名产认证系统

名产认证不是只体现在名产订单高价上。高价订单是它的一个出口，但不应该是唯一价值。

### 6.1 品种与产地分离

需要区分：

| 概念 | 来源 | 是否跟随种子移动 |
| --- | --- | --- |
| 品种 | 种子本身 | 跟随，例如厚皮葡萄种到哪里仍是厚皮葡萄 |
| 产地认证 | 本次种植地点和品质 | 不跟随，例如波尔多认证只来自波尔多葡萄园收获批次 |
| 风土样本 | 地貌掉落或认证奖励 | 可作为材料带走 |
| 名产共鸣 | 地貌和代表作物匹配时触发 | 只在对应地貌或指定国家生效 |

示例：

| 种植 | 收获结果 |
| --- | --- |
| 普通葡萄种在普通丘陵 | 普通葡萄 |
| 普通葡萄种在波尔多葡萄园 | 波尔多认证葡萄 |
| 厚皮葡萄种在波尔多葡萄园 | 波尔多厚皮葡萄，适合酿酒 |
| 波尔多厚皮葡萄种到托斯卡纳葡萄园 | 仍是厚皮葡萄，但失去波尔多认证，可能获得托斯卡纳日照品质 |

### 6.2 名产认证的用途

| 用途 | 说明 |
| --- | --- |
| 名产合约资格 | 某些高价合约只收指定认证批次 |
| 加工倍率 | 指定认证进入特定加工线时提高品质或产出价值 |
| 国家声望 | 首次认证、连续认证、批量认证都可提升国家声望 |
| 风土样本 | 认证收获可掉落地貌样本，用于研究和育种 |
| 配方解锁 | 达成某认证次数后解锁当地配方 |
| 展馆 / 图鉴 | 收集不同国家和地貌认证，形成长期目标 |
| 贸易路线 | 高级玩法中，认证作物可进入跨国贸易订单 |

### 6.3 认证规则

```json
{
  "certificationId": "bordeaux_origin",
  "name": "波尔多认证",
  "requiredOriginBiomeIds": ["fr_bordeaux_vineyard"],
  "eligibleSpeciesIds": ["grape"],
  "eligibleTraitIds": ["thick_skin", "wine_aroma", "deep_color"],
  "minQuality": "B",
  "effects": {
    "specialtyOrderValueMultiplier": 1.55,
    "wineProcessingQualityBonus": 0.18,
    "countryReputationBonus": {
      "fr": 8
    },
    "terroirSampleDropChance": 0.08
  }
}
```

认证不一定只给代表作物。可以分为：

| 认证类型 | 说明 |
| --- | --- |
| 严格名产认证 | 只给代表作物，例如波尔多葡萄 |
| 风土认证 | 给适配风土的其它作物，例如波尔多砾石风土番茄 |
| 活动认证 | 节日或限时规则，例如春节红果认证 |

第一版先做严格名产认证，后续再开放风土认证。

## 7. 研究点系统

研究点是连接变异、加工和育种的长期资源。

### 7.1 研究点来源

| 来源 | 示例 |
| --- | --- |
| 研究订单 | 提交变异线索、不稳定种子、风土样本 |
| 首次发现 | 首次发现一个变异性状或名产认证 |
| 育种失败补偿 | 失败后给少量研究点，保证尝试不完全浪费 |
| 加工熟练度里程碑 | 某配方达到等级后给研究点 |
| 国家研究任务 | 完成某国特色作物链 |

### 7.2 研究点用途

| 用途 | 说明 |
| --- | --- |
| 解锁环境配方 | 干旱筛选、寒冷诱导、盐碱筛选、强光增甜 |
| 提高指定育种组合成功率 | 只对某个组合、某个物种或某类性状生效 |
| 提高线索转种子效率 | 让变异线索更稳定地变成不稳定种子 |
| 提高稳定培养成功率 | 缩短从不稳定种子到稳定品种的过程 |
| 解锁加工模块 | 例如发酵工坊的酒桶模块、烘干坊的茶叶模块 |
| 解锁预测信息 | 显示更多可能育种结果和旁支方向 |
| 降低失败损失 | 失败时返还部分材料或保留亲本 |

可以允许研究点提升某个组合的成功率，但不建议做成全局永久 `+50% 育种成功率`。更好的方式是研究项目。

```json
{
  "researchUpgradeId": "rice_frost_drought_breeding_01",
  "name": "霜旱稻育种方案 I",
  "costResearchPoints": 80,
  "scope": {
    "speciesId": "rice",
    "requiredTraitIds": ["drought_tolerant", "frostheart"]
  },
  "effects": {
    "targetComboSuccessBonus": 0.08,
    "unstableSeedChanceBonus": 0.10,
    "failureMaterialReturnBonus": 0.15
  }
}
```

这样研究点能明确服务玩家当前目标，不会让所有育种都一起膨胀。

### 7.3 研究方向

研究点可以是一个总资源，但研究树分方向。

| 研究方向 | 主要解锁 |
| --- | --- |
| 环境适应 | 耐旱、耐寒、耐盐等环境配方和稳定率 |
| 品质加工 | 甜、清香、油润、糯性等加工加成 |
| 形态产量 | 巨大化、厚叶、密穗等产量和形态性状 |
| 风土名产 | 名产认证、风土样本、国家合约 |
| 温室控制 | 育种槽位、参数调节、失败保护 |

前期可以只有“研究点”，后期再用研究树区分方向。

## 8. 二次育种系统

二次育种应该使用可调环境参数作为底层，但不要一开始把参数全部裸露给玩家。

### 8.1 开放层级

| 阶段 | 玩家操作 | 底层逻辑 |
| --- | --- | --- |
| 初级育种 | 选择亲本 + 选择目标方向 | 系统自动套环境配方 |
| 中级育种 | 选择亲本 + 环境配方 + 1-2 个强化项 | 玩家开始理解环境压力 |
| 高级育种 | 自定义温度、水分、光照、肥力、盐碱、控制度 | 玩家深度调参，追求稀有组合 |

第一版建议使用环境配方：

| 环境配方 | 倾向性状 | 风险 |
| --- | --- | --- |
| 干旱筛选 | 耐旱、深根、厚皮 | 失败率提高，产量型结果减少 |
| 寒冷诱导 | 耐寒、霜心、慢熟 | 时间更长 |
| 高湿培养 | 喜水、浮叶、水心 | 旱地性状容易冲突 |
| 盐碱筛选 | 耐盐、盐晶、厚皮 | 失败率高 |
| 强光增甜 | 甜、金纹、早熟 | 水分消耗高 |
| 高肥膨大 | 巨大化、厚叶、密穗 | 品质波动 |
| 温室稳定 | 稳定率高、稀有率低 | 惊喜少 |
| 高压诱变 | 稀有性状和旁支更多 | 失败和异常种子更多 |

### 8.2 育种流程

```text
1. 选择母本
2. 选择父本
3. 选择育种目标
4. 选择环境配方
5. 选择可选研究加成或风土样本
6. 开始本地时间倒计时
7. 获得结果：失败 / 回退 / 不稳定种子 / 目标新品种 / 旁支变异 / 稀有突破
8. 成功品种进入图鉴，可量产或继续作为亲本
```

界面信息：

```text
育种温室

亲本 A：耐旱稻
亲本 B：霜心稻

目标方向：适应 / 品质 / 形态 / 色彩 / 生长
环境配方：高原寒旱
可选投入：雪土样本、干根样本、研究点强化

预测：
目标成功率 32%
不稳定种子 28%
旁支方向：寒香 / 金穗
失败 22%
```

### 8.3 参数与取舍

底层参数建议沿用地貌属性：

| 参数 | 作用 |
| --- | --- |
| `moisture` 水分 | 影响耐旱、喜水、浮叶、水心 |
| `temperature` 温度 | 影响耐寒、耐热、霜心、烈阳 |
| `sunlight` 光照 | 影响甜、金纹、早熟、强光适应 |
| `fertility` 肥力 | 影响巨大化、高产、厚叶 |
| `salinity` 盐碱 | 影响耐盐、海风、盐晶 |
| `slopeStress` 坡地压力 | 影响矮生、深根、抗风 |
| `control` 可控度 | 提高成功率和稳定率 |
| `mutationPressure` 诱变压力 | 提高稀有和旁支概率，但增加失败 |

核心取舍：

```text
环境压力高 -> 更容易出新性状，但失败率高
环境控制高 -> 更容易稳定成功，但稀有惊喜少
亲本适配高 -> 成功率高，但突破少
亲本差异大 -> 可能出稀有组合，但失败率高
研究投入高 -> 可以把概率往指定目标拉，但不能完全消除旁支
```

### 8.4 结果分支

育种不要只有“成功 / 失败”。建议每次育种结算时生成一个分支池。

| 分支 | 说明 | 示例 |
| --- | --- | --- |
| 失败 | 未获得可种植结果，但给研究经验或返还少量材料 | 干枯试验苗 |
| 亲本回退 | 得到一个亲本方向的普通种子或不稳定种子 | 耐旱稻种子 |
| 目标不稳定 | 获得目标组合的不稳定种子 | 不稳定霜旱稻 |
| 目标稳定 | 直接获得目标稳定品种 | 霜旱稻 |
| 稀有突破 | 目标基础上附加高价值性状 | 霜旱清香稻 |
| 旁支变异 | 没走向主目标，但走向其它合理方向 | 寒香稻、金穗稻、矮穗稻 |

旁支变异的来源不是完全随机，而是由三类因素决定：

| 来源 | 如何影响旁支 |
| --- | --- |
| 亲本隐藏倾向 | 父母性状中未作为目标的标签可能被带出 |
| 环境偏移 | 配方中的非目标压力会把结果推向其它方向 |
| 风土样本 | 投入的地貌样本会把结果推向对应风土 |

例如目标是 `耐旱 + 霜心`，但环境中 `sunlight` 很高，可能旁支到 `金穗`；如果 `moisture` 偏高，可能旁支到 `水心`；如果投入波尔多砾石土样本，可能旁支到 `厚皮`。

### 8.5 多方向变异池

每个育种项目可以同时维护多个方向权重。

```json
{
  "breedingAttemptId": "attempt_rice_frost_drought_001",
  "parentVariantIds": ["cn_drought_rice", "cn_frostheart_rice"],
  "targetTraitIds": ["drought_tolerant", "frostheart"],
  "environmentRecipeId": "highland_cold_dry",
  "directionWeights": {
    "target_combo": 46,
    "parent_drought": 12,
    "parent_frost": 12,
    "cold_aroma_side": 10,
    "golden_grain_side": 6,
    "unstable_unknown": 8,
    "failure": 6
  }
}
```

玩家投入研究点时，不是把失败率简单清零，而是把概率往目标方向移动：

```text
研究点强化前：
目标组合 46，旁支 16，亲本回退 24，不稳定未知 8，失败 6

研究点强化后：
目标组合 58，旁支 13，亲本回退 18，不稳定未知 6，失败 5
```

研究点可以降低失败和回退，但仍保留少量旁支，保证系统有发现感。

### 8.6 结果示例

```text
亲本：耐旱稻 x 霜心稻
目标：适应 + 色彩
环境：高原寒旱
投入：雪土样本 x1，研究点强化 I

可能结果：
35% 不稳定霜旱稻
24% 霜旱稻
8% 霜旱清香稻
10% 寒香稻
7% 矮穗稻
6% 亲本回退
10% 失败，但获得研究经验
```

这套结果让失败有成本，但不会把玩家推入纯挫败。旁支结果也可以进入图鉴或作为新育种亲本。

## 9. 首版落地范围

第一版不要一次做完整系统，建议分阶段：

| 版本 | 内容 |
| --- | --- |
| V1 | 统一订单系统：日常订单 + 中国国家订单 |
| V2 | 三个加工建筑：农家厨房、谷物磨坊、发酵工坊 |
| V3 | 名产认证：只做代表作物严格认证和名产合约 |
| V4 | 初级育种：同物种亲本 + 环境配方 + 不稳定种子 |
| V5 | 研究点：解锁环境配方、提高指定组合成功率、降低失败损失 |
| V6 | 旁支变异：加入方向权重、风土样本和稀有突破 |

第一批建议只实现：

- 中国 3 个地貌。
- 5 个基础作物。
- 3 个加工建筑。
- 10-15 个加工配方。
- 4 个一级变异方向。
- 3 条同物种二次育种组合。
- 1 个名产认证样例。

## 10. 关键规则

- 作物经济价值不能只靠订单价格，要同时服务加工、名产、育种、图鉴和国家进度。
- 订单系统底层统一，国家和名产通过频道、条件和奖励体现。
- 加工建筑保持少量大类，配方和模块负责扩展内容。
- 名产认证是收获批次属性，不是种子的永久属性。
- 名产认证的价值包括订单资格、加工加成、风土样本、声望、配方和图鉴。
- 研究点可以提高指定育种组合成功率，但要通过项目、物种或性状范围限制。
- 二次育种底层使用环境参数，前期用环境配方包装，后期开放高级调参。
- 育种分支要包含目标结果、旁支结果、亲本回退、不稳定种子和失败补偿。
- 旁支方向由亲本隐藏倾向、环境偏移和风土样本决定，不做完全无解释的随机。
