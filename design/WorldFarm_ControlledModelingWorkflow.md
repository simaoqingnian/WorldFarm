# WorldFarm 可控建模流程

本文固化 WorldFarm 后续作物、地貌、地块和建筑资产的可控建模方法。核心目标是把“我想要一个满意的 3D 模型”拆成可描述、可评审、可锁定、可回退的阶段，避免只靠自然语言反复微调模型。

## 1. 基本原则

WorldFarm 不把“一句话直接生成最终模型”作为正式资产流程。

正式流程采用：

```text
风格规范
-> 资产需求卡
-> 轮廓规格
-> 2D 轮廓确认
-> Blender 灰模
-> Unity/Tuanjie 预览
-> Android 实机检查
-> 正式模型和材质
-> 锁定资产版本
```

每个阶段只验收当前阶段应该决定的内容。已经通过的部位记录为 `locked`，除非用户明确要求，否则后续不再主动修改。

## 2. 为什么这样做

自然语言可以表达方向，但不适合直接控制复杂三维形体。胡萝卜资产试验中已经验证：

- “顶部圆润”“底部不要尖”“叶子自然”这类描述容易被模型或程序理解成不同形状。
- 一个局部修改可能牵连另一个已通过局部，例如顶部改动影响主体轮廓。
- 如果没有锁定记录，后续很容易把已经满意的部分改坏。
- 如果没有三视图和控制点，反馈只能停留在“像不像”，修改不可控。

因此正式流程必须保留：需求卡、控制点、截图、反馈记录、源文件、导出文件和 Unity 预览状态。

## 3. 阶段 0：风格规范

在批量建模前先固定项目总风格。

当前 WorldFarm 风格基准：

```text
风格名称：轻写实圆润农场 3D
核心感受：干净、温和、明亮、可识别，有一点夸张但不幼稚
目标平台：安卓手机，竖屏优先
主视角：农场经营界面偏俯视 3D，详情页允许单个资产旋转展示
模型复杂度：中低面数、圆润大轮廓、少碎细节
材质方向：干净色块 + 柔和高光 + 少量生长纹理
单屏目标：20 个左右作物仍能清楚识别
```

后续所有资产默认沿用这套风格，除非文档明确建立新风格分支。

## 4. 阶段 1：资产需求卡

每个正式资产从需求卡开始。

模板：

```text
资产名称：
资产类型：作物 / 地貌 / 地块 / 建筑 / 道具 / UI展示模型
国家/区域：
地貌：
品种或变异类型：
用途：地块中显示 / 详情展示 / 图鉴 / 商店 / 任务演出
成长阶段：种子 / 幼苗 / 成长 / 成熟 / 枯萎 / 变异
是否需要动画：
是否需要图标：
重点验收：
禁止方向：
```

如果用户没有补充，默认使用项目基础风格，并先做成熟阶段单体资产。

## 5. 阶段 2：轮廓规格

轮廓规格用于把审美需求转换成可建模参数。

常用参数：

```text
高度/宽度比例
最宽点位置
顶部、底部、侧面处理
是否对称
是否允许自然弯曲
是否允许表面纹理参与轮廓
是否需要变异特征
```

对根茎类作物，优先确定：

- 主体高度和最大宽度。
- 最宽点在上部、中部还是下部。
- 底部是尖、钝、圆还是截断。
- 顶部是叶簇遮盖、可见肩部还是明显发叶口。
- 侧面是圆、扁还是厚椭圆。

轮廓规格应同时保存 Markdown 和 JSON：

```text
ArtSource/Crops/<AssetName>/specs/shape_profile_v001.md
ArtSource/Crops/<AssetName>/specs/shape_profile_v001.json
```

## 6. 阶段 3：2D 轮廓确认

2D 阶段只看剪影和关键控制点，不看材质。

输出：

```text
refs/<asset>_silhouette.svg
refs/stage2_review.md
```

用户反馈应尽量落在控制点或局部：

```text
主体：通过 / 太胖 / 太瘦 / 太高 / 太矮 / 不够平滑
顶部：通过 / 太窄 / 太宽 / 像平台 / 像碗 / 叶簇方向不对
叶簇：通过 / 太多 / 太少 / 太细 / 太粗 / 不够卡通
底部：通过 / 太尖 / 太平 / 太宽 / 太窄 / 不够圆润
侧面：通过 / 太厚 / 太薄 / 不够直
```

通过项必须写入 `feedback.md` 和规格文件，状态改为 `locked`。

## 7. 阶段 4：Blender 灰模

Blender 灰模用于验证三维体块是否成立。

输出：

```text
blender/<asset>_blockout.blend
blender/create_<asset>_blockout.py
exports/<asset>_blockout.fbx
screenshots/<asset>_blockout_front.png
screenshots/<asset>_blockout_side.png
screenshots/<asset>_blockout_three_quarter.png
screenshots/<asset>_blockout_top.png
```

本阶段只看：

- 正面、侧面、三分之四视角和俯视是否都成立。
- 体块是否符合 2D 已通过轮廓。
- 已锁定部位是否被保持。
- 是否存在不自然拼接、尖点、球盖、平面、波浪、横向环带等基础形体问题。

本阶段不看：

- 最终贴图。
- 最终材质。
- 细节纹理。
- 叶脉。
- 图标效果。
- 成长阶段差异。

重要规则：

- 灰模可以使用临时颜色区分部件，但临时颜色不代表最终材质。
- 如果某个局部通过，后续只修改未通过局部。
- 如果灰模反复出现局部问题，应修改生成脚本或控制点，而不是只改截图表现。

## 8. 阶段 5：Unity/Tuanjie 预览

Blender 灰模通过后，进入 Unity/Tuanjie 预览。

目标：

- 检查模型导入后的朝向、缩放、光照、阴影、地块比例和手机竖屏构图。
- 检查触控旋转或自动旋转时是否好看。
- 检查同屏多个资产时是否过大、过小、太暗、太乱。

预览资产放入：

```text
UnityProject/Assets/WorldFarm/Resources/AssetPreview/<AssetName>/
```

预览场景：

```text
UnityProject/Assets/WorldFarm/Scenes/AssetPreview.unity
```

APK 输出：

```text
Builds/Android/WorldFarm-dev.apk
```

本阶段用户反馈格式：

```text
屏幕大小：通过 / 太大 / 太小
位置：通过 / 太靠上 / 太靠下 / 出边界
旋转：通过 / 侧面不好看 / 背面不好看 / 轴心不对
光照：通过 / 太暗 / 太亮 / 高光不舒服
和其它资产：通过 / 风格不一致 / 太抢眼 / 不够明显
是否进入正式模型：是 / 否
```

## 9. 阶段 6：正式模型和材质

Unity 预览通过后，才进入正式细化。

正式阶段可以添加：

- 表皮细节。
- 低频生长纹。
- 叶脉。
- 轻微不对称。
- 更完整材质。
- 成长阶段。
- 图鉴图标。
- 收获动画或待机动画。

正式阶段不能破坏已锁定的大轮廓、比例、顶部连接、底部处理和侧面厚度。

## 10. 版本和锁定规则

每个资产使用稳定编号：

```text
Crop_Carrot_Normal_v001
Crop_Carrot_Drought_v001
Biome_China_TemperatePlain_v001
```

每轮反馈都写入：

```text
ArtSource/<Type>/<AssetName>/feedback.md
```

状态建议：

```text
brief_in_progress
silhouette_in_review
silhouette_passed
blockout_in_review
blockout_passed
unity_preview
unity_preview_passed
modeling_in_progress
model_passed
locked
```

锁定规则：

- 用户说“通过”“满意”“不要改了”，对应局部立即锁定。
- 修改未通过局部时，不能主动改变锁定局部。
- 如必须影响锁定局部，先说明影响范围，再等用户确认。
- 旧方案可以保留在 Git 历史里，但当前文档只记录最新有效状态。

## 11. 当前胡萝卜实践结论

资产：

```text
Crop_Carrot_Normal_v001
```

当前状态：

```text
Blender 灰模通过，进入 Unity/Tuanjie 预览
```

已通过并锁定：

- 主体：平滑倒圆锥，P4 附近最宽。
- 顶部：叶茎从橙色顶部中心区域长出。
- 叶簇：4 根卡通直立粗叶茎。
- 叶簇末端：无球盖、无小突起，使用钝端。
- 底部：窄而圆润的钝头。
- 侧面：加厚后通过。

本次流程验证出的长期规则：

- 根茎类作物要先锁定主体轮廓，再处理叶簇。
- 叶簇末端不要用独立球体端盖，容易显得像套上去。
- 单点封口容易产生小突起，灰模阶段应避免。
- 灰模阶段不要用明显几何环纹表达生长纹，容易破坏主体轮廓。
- 用户确认通过的局部应马上冻结，不随其它局部修改反复变化。
